# Jarvis GUI control

Jarvis uses [Cua Driver](https://github.com/trycua/cua/tree/main/libs/cua-driver) for GUI observation and pointer actions. [agent-computer-use](https://github.com/kortix-ai/agent-computer-use) describes itself as no longer maintained and directs users to Cua. Cua also has a documented [Omarchy integration](https://cua.ai/docs/cua-sdk/guides/omarchy).

The voice agent exposes window discovery, accessible-element inspection, exact-window verification, desktop observation, left-clicking, scrolling, typing, and key or shortcut input. It can also open a separate isolated Chrome, bind an exact browser window and tab, inspect semantic page refs, navigate, type, click, and double-click. For accessible apps it uses exact window IDs and fresh element tokens. If the accessibility result is degraded, it uses a current desktop image and coordinates. Coordinate actions require a frame that was actually submitted to the Live model. After each action the agent must observe again; Cua can report `effect: unverifiable` even when the action reached the app.

The installed driver is optional. If it is missing, Jarvis excludes these skills and retains its existing Hyprland window controls, `wtype` typing and shortcuts, and screen inspection. When present, Jarvis starts the driver on first use with native Wayland enabled on Hyprland. The driver runs without its overlay. These actions are bounded to a recent 15-second observation, and the driver receives arguments as JSON through an argv list rather than a shell.

On this host, a disposable GTK button was activated through Cua's desktop coordinate route and then through its accessibility token route. A disposable text field received Cua typing and an Enter key. An isolated Chrome tab navigated to a local test page, accepted text, activated a button, and received a double-click. The browser's trusted background click was refused; Jarvis now starts with Cua's working DOM-event route for its isolated browser and confirms the page change with a new snapshot. Window discovery and desktop capture worked; the driver accepted a scroll action without verifying its effect. [Cua's platform guide](https://cua.ai/docs/cua-driver/concepts/platform-support) still calls Hyprland/Omarchy experimental. Some existing windows return degraded accessibility identity. Native Wayland drag failed in testing, so it is not exposed to Jarvis. Untested desktop right/middle clicks and other browser gestures were removed from the voice tool list. Jarvis cannot safely use element tokens for degraded windows. This integration does not claim that every application can be controlled or that a click had the intended effect without observing the result.

To troubleshoot, check `cua-driver status` and `cua-driver doctor` in the desktop session, then ask Jarvis to list GUI windows and observe the desktop. A `frame_submitted` result means it received a usable visual frame; an `ocr_only` or error result means it must not click coordinates. Run the focused tests with `.venv/bin/python -m unittest tests.test_core.test_agent tests.test_skills.test_gui_control -q`.
