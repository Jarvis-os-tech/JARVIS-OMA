# PC voice subsystem lock

Locked on 2026-11-04 at the user's explicit request. The exact file hashes and original permissions are in `audio/.voice_lock.json`.

The complete `voice_layer/`, `jarvis_voice/` and `audio/` source/assets are frozen, together with the listed legacy core voice files, voice entry points, service units, configuration example and regression tests. These paths are read-only locally. Generated bytecode caches remain writable and are excluded. Runtime profiles, recordings, credentials and mutable service state are not copied into the baseline. Shared UI/application code and Android are outside this PC-engine boundary.

`python scripts/verify_voice_lock.py` checks changed, missing, redirected and newly added protected files. CI runs it and the required behavior gate exercises the verifier's failure cases. The existing evolution guard also reads the same manifest's `locked_files` paths. Root `CLAUDE.md` and its `AGENTS.md` mirror require explicit user authorization before altering or bypassing the subsystem.

No voice service restart or microphone setting change is part of locking. Read-only inspection and existing tests remain allowed. Say “unlock the voice subsystem” when changes are wanted; the agent must preserve the recorded original modes and establish a newly approved baseline, rather than silently accepting a mismatch.

This prevents accidental edits and makes drift detectable. The machine owner can deliberately change permissions or the baseline; it is not a root-owned immutable filesystem. Git does not preserve read-only permission bits, so new clones rely on the policy and checksum check until local read-only permissions are applied.
