# Context-aware activation greetings

The default activation prompt asks the voice model to compose a fresh sentence,
using the local time and up to 20 recent, scanner-filtered conversation messages.
It can mention one unfinished task or unresolved issue and offer a next step.
It must exclude completed, cancelled, superseded and declined work, qualify
uncertain status, and never launch a task merely because it appears in history.
This uses the existing Gemini Live response, with no extra model request.

`greetings.db` in the configured memory directory stores activation timestamps,
the fingerprint of the latest user message, and recent spoken greeting text.
The same saved context is not supplied as a new reminder twice. Recent greeting
wording is supplied as examples to avoid; wording is generated by the model, so
this is not a guarantee that it can never use the same phrase. An interrupted
greeting records the partial transcription when available. A sent activation
counts for suppression even if playback is interrupted.

Under `[agent]`, `greeting_cooldown_seconds` defaults to 14400: restarting within
four hours on the same local calendar day does not trigger another greeting.
The next day permits a new welcome, without reoffering unchanged context.
Set the cooldown to 0 to greet on every process activation. Reconnecting within
one running voice process still greets only once. `greeting_resume_work = false`
disables work reminders while retaining welcome variation and suppression.
`greet_on_activation = false` disables greetings entirely. An explicit
`greeting_prompt` remains an exact custom override of this dynamic policy.

Cross-restart suppression requires enabled memory and desktop skills. With
conversation recording disabled, no prior conversation is invented. Context
and greeting-history operations run on a worker thread. A memory read failure
falls back to a varied welcome. No service restart or live voice test is performed
when editing this implementation; new settings take effect when JARVIS restarts.
